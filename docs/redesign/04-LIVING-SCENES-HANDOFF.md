## Part 1 — Where this project is (the entire plan so far)

### 1.1 The one-paragraph story
Drive Exotiq is the community front door to the exotiq.rent exotic-car marketplace. The owner (Gregory Ringler) dictated a cinematic script — garage door opens → fly through a supercar lineup → choose a car → get in → push-to-start → the road → the coast → arrival → call to action. We refined it into a red-teamed 24-beat storyboard, rendered it as B&W charcoal director's sketches, then as **photoreal stills on one locked film-noir grade**, and built it as a working scroll film at **`/experience`**: one pinned viewport, 24 plates cross-dissolving with ken-burns drift, copy resolving over the top, driven by a single Lenis-eased scroll progress. The page is verified working (TS clean, HTTP 200, walked end-to-end in Chrome). **The next mandate — this handoff — is to make every scene *live*: film-style motion per beat, the cars moving, the gauge sweep animated, content pushed to Hollywood grade using the best current image/video generation models.**

Two audiences, two desires, one scroll:
- **Movement I — "The Experience" (renters), SB-01→SB-16.** Sells *the exotic drive itself*: garage → fleet cards (McLaren 720S / Porsche GT3 RS / Lamborghini+Ferrari) → choose your car → dihedral door → cockpit → ignition → road → coast. The driven hero is the **McLaren 720S**.

**Hard-won implementation learnings (respect these):**
1. **Plate-band math:** copy block *k* centers at progress `k/(N−1)` — media fade bands MUST use denominator `N−1`, not `N`, or media/copy drift apart down the page (this bug shipped and was fixed; see `CinematicStage.tsx` comments).
2. **OpenRouter Images API:** `POST https://openrouter.ai/api/v1/images` `{model, prompt, aspect_ratio}` → `data[0].b64_json`. `input_references` accepts **base64 data URLs** (downsize refs to ≤1000px/q60 first — large payloads throw `fetch failed`; retry with backoff is wired in the scripts).
3. `google/gemini-2.5-flash-image` via OpenRouter returned a **Google-side 403 dunning error** — don't assume Gemini image works through OpenRouter; verify or go direct.
4. gpt-image-1 renders **garbled text on objects** (an "ENSUNE START" button shipped once) — prompt "absolutely no lettering/symbols"; inspect every render.
5. Lenis eats keyboard scrolling in automation; `window.scrollTo` + a wheel nudge syncs it. Fast-refresh remounts flash plate 0 momentarily (progress resets) — transient, not a bug.
6. Everything media-heavy is a client island; **Netlify SSR** — `window`/WebGL access must be `next/dynamic {ssr:false}`.

## 2.1 Video generation (image-to-video) — the core capability

As of July 2026 the image-to-video field has consolidated around three production-grade closed models — Google Veo 3.1, Kling 3.0, and ByteDance Seedance 2.0 — all of which accept our graded stills as first frames, support first+last-frame control, and are callable through the OpenRouter async video endpoint (POST /api/v1/videos) using the OPENROUTER_API_KEY already in .env.local, so the existing scenes-photoreal.mjs pipeline pattern extends directly to video. OpenAI Sora is effectively dead (app discontinued 2026-04-26, sora-2/sora-2-pro API sunsets 2026-09-24) and must not be built on. For the Exotiq living-scenes phase: use Veo 3.1 (veo-3.1-generate-preview, $0.20/s no-audio 1080p, iterate on Fast at $0.08-0.10/s) as the hero engine for one-shot cinematic moves (dihedral door lift, gauge sweep, drive-by) because it has the best temporal coherence and fewest morphing artifacts on photoreal cars; use Kling 3.0 Pro's start_image_url + end_image_url with the same frame ($0.112/s, 3-15s) to make mathematically seamless ambient loops that return exactly to our graded still, with Luma's native loop:true flag as the convenience backup; use Hailuo 2.3 ($0.0817/s flat, 1080p) and Veo 3.1 Fast's video-extension chain (+7s per extend, up to 148s at 720p) for POV driving plates. Seedance 2.0's reference-to-video (up to 4K, 15s, ~$0.15/s at 720p via OpenRouter) is the identity-lock backup wherever the S8's IMSA livery must survive aggressive motion. Known failure modes to QA for on every render: rotating wheel spokes morphing, grille-mesh warping, badge/plate text artifacts, and paint reflections swimming — cars are the single hardest consistency genre, which is exactly why animating from our locked stills (rather than text-to-video) is the right architecture. A full 24-beat pass at 8s/beat on Veo 3.1 no-audio costs roughly $38; even 10 iteration passes is ~$400, so budget is genuinely a non-issue.

**Recommendation:** Stack, by job: (a) SEAMLESS AMBIENT LOOPS — primary Kling 3.0 Pro via OpenRouter (kwaivgi/kling-v3.0-pro) or fal, start_image_url = end_image_url = the beat's graded still, 5-8s, generate_audio:false at $0.112/s → a $0.56-0.90 loop that returns pixel-exact to our still (no crossfade hack, no visible seam under the ken-burns stage); backup Luma Dream Machine API with loop:true (only native loop flag in the industry) for atmosphere-only plates, and Veo 3.1 first=last-frame interpolation as tiebreaker. (b) ONE-SHOT CINEMATIC MOVES (SB-09 door lift, SB-11 ignition sweep, SB-11b roll-out, SB-19 livery reveal) — primary Veo 3.1: iterate on veo-3.1-fast-generate-preview ($0.08-0.10/s no-audio), finalize on veo-3.1-generate-preview at 1080p/8s no-audio ($0.20/s ≈ $1.60/shot), using our still as `image` plus up to 3 referenceImages (S8 refs + livery ref) to hold identity; backup Seedance 2.0 reference-to-video (first+last frame, 15s, ~$0.15/s 720p / $0.34/s 1080p via OpenRouter) wherever the wrap livery or founder likeness drifts in Veo takes. (c) POV DRIVING PLATES (SB-03, SB-12/13/15) — primary Hailuo 2.3 (minimax/hailuo-2.3, $0.0817/s, native 1080p, 10s) for maximum believable speed energy; backup Veo 3.1 Fast with the extension API (+7s per call, to 148s at 720p) when a beat needs a long continuous run. Do NOT build on Sora (API dies 2026-09-24); skip Runway for generation (keyframe API not shipped for Gen-4.5) but keep Aleph 2 ($0.28/s) in reserve to relight/cleanup the real S8 and founder footage. Integration: extend the existing scenes-photoreal.mjs into a scenes-motion.mjs targeting OpenRouter POST /api/v1/videos (same key, async submit+poll, frame_images for first/last frame, b64 stills as data URLs) with per-beat model routing; only Luma and fal need new keys, which the owner has approved. Serve results as ≤8s muted AV1/HEVC loops (buy no-audio SKUs, 33-50% cheaper) with the current stills as poster/fallback so the reduced-motion and slow-connection ship-gates keep passing. Expected spend for a selective 5-take pass over all 24 beats: under $250.

### Google Veo 3.1 (primary hero engine)

Model ids veo-3.1-generate-preview / veo-3.1-fast-generate-preview / veo-3.1-lite-generate-preview via Gemini API (Veo 3.0 shut down 2026-06-30). I2V via `image` param; `lastFrame` gives first+last-frame interpolation; `referenceImages` accepts up to 3 style/subject refs (3.1 + Fast only); `video` param extends prior generations +7s per call up to 20x / 148s total (720p only). Durations 4/6/8s (must be 8s for 1080p/4K/refs/extension), 16:9 or 9:16, 720p/1080p/4K, native synced audio. Gemini API pricing per second: Standard $0.40 w/audio ($0.20 no-audio, $0.60 4K); Fast $0.10-0.12 w/audio ($0.08-0.10 no-audio); Lite $0.05-0.08. Same SKUs on OpenRouter as google/veo-3.1[-fast|-lite] with first_frame+last_frame and seed support.

**Fit for this project:** Best-in-class temporal coherence and fewest morphing artifacts on photoreal vehicles — the right engine for the money shots: SB-09 door lift, SB-11 ignition/gauge sweep, SB-19 livery reveal. Iterate cheaply on Fast, finalize on Standard no-audio (our page is muted anyway); the 8s cap per shot matches our beat length, and first=last-frame interpolation doubles as a loop fallback.

### OpenAI Sora 2 / Sora 2 Pro (avoid)

Sora consumer app discontinued 2026-04-26; sora-2, sora-2-pro and the entire Videos API are deprecated with a hard shutdown 2026-09-24 and no announced successor. Until then: i2v supported, durations 4-20s, 720p $0.30/s and 1080p $0.50/s for Pro ($0.10/s standard), also reachable as openai/sora-2-pro on OpenRouter. No first/last-frame control (frame_images: null on OpenRouter).

**Fit for this project:** Non-starter: any pipeline built on it dies in under 3 months. Physics quality is real but irrelevant given the sunset; exclude from the Exotiq stack entirely.

### Kling 3.0 (Kuaishou) — loop and product-lock specialist

fal endpoints fal-ai/kling-video/v3/{pro|standard}/image-to-video plus a v3/4k endpoint; OpenRouter kwaivgi/kling-v3.0-pro|std and multi-shot kwaivgi/kling-video-o1. Params: start_image_url (required), end_image_url (optional — true start/end-frame control), duration 3-15s, generate_audio, elements[] custom object refs, multi_prompt multi-shot, negative_prompt, cfg_scale. Pricing: Pro $0.112/s no-audio, $0.168/s audio; Standard $0.084/$0.126; 4K flat $0.42/s. Avoid Kling's direct API (prepaid packages from ~$4,200); fal/OpenRouter are pay-per-second.

**Fit for this project:** Reputation for the most stable motion physics on locked product shots — least likely to melt the 720S's bodywork. Setting end_image_url = start_image_url produces a mathematically seamless loop that lands back exactly on our graded still, making it the primary engine for ambient breathing plates (SB-01 covered car, SB-04 fleet aisle, SB-10 cockpit dawn).

### Runway Gen-4.5 / gen4_turbo — secondary, plus Aleph 2 for footage editing

API at docs.dev.runwayml.com, credits at $0.01: gen4.5 = 12 credits/s ($0.12/s), 2-10s, 480p-1080p plus new native 4K ratio values (e.g. 3840x2160) on T2V/I2V/V2V endpoints; gen4_turbo = $0.05/s; aleph2 (video-to-video edit/relight) = $0.28/s. Gen-4.5 API currently exposes text- and image-to-video; keyframes and other control modes still 'coming' — Motion Brush 3.0 and Director Mode camera controls remain app-side, so API camera moves are prompt-described. Runway also resells seedance2 (up to $1.50/s at 4K) and veo3.1.

**Fit for this project:** Strong cinematic B-roll and 10s-hold consistency, but for pure i2v from our stills it's outclassed on price/control by Veo and Kling since its keyframe API isn't shipped for 4.5 yet. Keep for one niche: Aleph 2 can relight/modify the REAL S8 and founder footage (SB-17/18/19b) — a capability none of the generators have.

### Luma Ray 3.14 / Ray3 (Dream Machine API) — only native loop flag

POST https://api.lumalabs.ai/dream-machine/v1/generations with keyframes.frame0/frame1 (start/end images) and a first-party `loop: true` parameter — unique among major APIs; resolutions 540p/720p/1080p/4K, 5s/10s plus extend. Official docs still list ray-2/ray-flash-2 model params while Ray 3.14 (released 2026-01-26: native 1080p, 4x faster, ~3x cheaper at 720p) is default in the product and documented by third parties; Ray3 base keeps HDR/EXR and character ref. Credit economics roughly 100 credits per 720p/5s and 800 per 1080p/10s on Ray 3.14; API billed separately from web plans (~$0.32+/generation entry).

**Fit for this project:** The native loop flag makes it the lowest-effort path to seamless ambient loops, and 16-keyframe direction (product-side) is interesting for choreographed moves. But fine mechanical detail on cars sits a tier below Veo/Kling/Seedance, so use it as loop backup and for atmosphere-only plates (fog, light blades) where car geometry isn't stressed.

### MiniMax Hailuo 2.3 — cheapest 1080p motion energy

OpenRouter minimax/hailuo-2.3: flat $0.0817/s, 1080p 16:9 only, 6s or 10s, first_frame i2v only (no end frame), no native audio, passthrough prompt_optimizer/fast_pretreatment. Direct MiniMax API is enterprise package-based ($1,000+/mo video-point bundles: Hailuo-2.3-Fast 768p/6s = 0.7 points); fal also hosts hailuo-02 at $0.045/s 768p.

**Fit for this project:** Community reputation for the most aggressive believable dynamic motion — speed, drift, camera rush — at the lowest 1080p price in the field. Primary candidate for POV driving plates (SB-12 open road, SB-13 mountain, SB-15 coastline) where raw motion energy matters more than badge-level detail; no end-frame control rules it out for loops.

### ByteDance Seedance 2.0 + 1.5 Pro — identity-lock and multi-shot

OpenRouter bytedance/seedance-2.0 (and -fast, seedance-1-5-pro); fal bytedance/seedance-2.0/{image-to-video|reference-to-video|fast}. Seedance 2.0: 480p-4K, 4-15s, first+last frame, reference-to-video (multiple images/videos guide identity), multi-shot prompting, audio included; token-priced ((w*h*24*sec)/1024 tokens): via OpenRouter $0.000007/token ≈ $0.15/s at 720p, $0.34/s at 1080p, ~$1.36/s 4K (fal charges $0.014/1K, ~2x OpenRouter at HD). Seedance 1.5 Pro: 12s max, 1080p, dual-branch AV generation, ≈$0.058/s no-audio 1080p — remarkable value. Watch the watermark passthrough param.

**Fit for this project:** Strongest subject-consistency reputation of the 2026 crop — reference-to-video can pin the S8's heritage IMSA livery across aggressive moves, directly protecting the SB-19 money frame. Use as backup for hero moves and as primary wherever the wrap or founder likeness must not drift; 15s duration also covers longer beats Veo can't do in one shot.

## 2.4 Award-site scroll-film engineering

Award-winning automotive/luxury scroll films are almost never one long scrubbed video; they are hybrid stages that layer (a) short muted ambient loops, (b) a few surgically-chosen scrub moments, and (c) GPU-parallaxed stills, all driven by one scroll progress — exactly the shape CinematicStage already has. Scrub-on-currentTime works well only with all-intra encodes (ffmpeg -g 1/-g 2 H.264 baseline yuv420p, plus a keyint=2 VP9 .webm twin for Firefox); AV1 is disqualified as the universal codec because Apple ships no software decoder (hardware only on A17 Pro/M3+). iOS Safari is the binding constraint: ~384MB total canvas memory (224MB on some WebKit builds), autoplay silently blocked in Low Power Mode, and no video prebuffering on mobile — so every plate needs a poster-still fallback and promise-checked play(). Keep the Lenis + framer-motion 12 stack: useScroll rides the native ScrollTimeline GPU path and one progress value already drives the stage; GSAP ScrollTrigger only pays off for multi-timeline pin choreography you don't need (and Lenis has a documented GSAP-ticker bridge if that ever changes). For the gauge sweep, Rive (state machines + data binding, ~200KB gzipped WebGL runtime, files ~10x smaller than Lottie) is what OFF+BRAND used on the Awwwards SOTD/FWA Lando Norris McLaren site. Move the ~40-100MB of video to Cloudflare R2 ($0.015/GB-mo, zero egress, byte-range MP4 for scrubbing) because Netlify's 2026 credit pricing meters bandwidth at 20 credits/GB against 300 (free) / 1,000 (Pro) monthly credits — a few hundred visitors of video would exhaust it. Recommended architecture: three media tiers per plate (ambient loop / all-intra scrub segment / depth-map 2.5D still), windowed mounting of ±1 plate, still-first crossfade so the existing PNG pipeline remains the LCP and reduced-motion path.

**Recommendation:** Keep Lenis + framer-motion 12 and the single-scroll-progress CinematicStage; do not add GSAP. Upgrade the 24 plates into a three-tier media stack, all driven by the existing progress value and all poster-anchored so the current stills remain the LCP, reduced-motion, low-power, and slow-connection path. (1) Tier A — ambient loops (~18-20 beats): generate 5s seamless 1080p loops image-to-video from each graded still; encode H.264 High CRF 18-20 (-an) with an HEVC or AV1 <source> variant; muted+playsinline+loop+poster(current PNG), preload=none until the plate is within 2 bands, promise-checked play() falling back to the still. (2) Tier B — scrub segments (2-3 beats max: SB-09 door lift, SB-02 door blade, optionally SB-19 wrap reveal): 2-4s all-intra encodes (libx264 baseline yuv420p -g 2 + VP9 keyint=2 webm twin), currentTime driven from a plate-local progress via useMotionValueEvent with seek-gating on 'seeked'; desktop may upgrade to a WebCodecs 20-frame sliding-window canvas, but never exceed ~200MB decoded frames on iOS (384MB canvas ceiling). (3) Tier C — 2.5D depth-parallax stills (everything else, incl. the real S8/founder photos): one R3F client-island (ssr:false) fullscreen-quad shader displacing UVs by an AI-generated depth map (MiDaS/Depth-Anything or gpt-image-1 depth pass through the existing OpenRouter pipeline), plus shared grain/vignette uniforms matching the locked grade. Build the SB-11 gauge sweep in Rive (scroll-progress number input driving needle/RPM state machine, Gulf-blue tick as the one accent). Mount media windowed (active plate ±1), keep the cross-dissolve logic and N-1 band math unchanged — a plate is just still→(fade in living layer)→still. Serve all video from Cloudflare R2 (zero egress, byte-range support; ~70MB total fits the free tier) on a media subdomain with immutable cache headers; convert posters to AVIF/WebP and keep them on Netlify. This is the same hybrid recipe behind the awarded references (OFF+BRAND's WebGL+Rive, Igloo's staged loading, Apple's poster-first scrub) and it upgrades every beat to 'living' without risking the mobile/perf ship-gates.

### Scroll-scrubbed video encoding (currentTime technique)

Scrubbing via video.currentTime is only smooth when nearly every frame is a keyframe: ffmpeg `-vcodec libx264 -pix_fmt yuv420p -profile:v baseline -level 3 -an -preset veryslow -g 2` (jeffpamer gist; muffinman.io tested -g 1..10). Browser matrix (muffinman.io tests): desktop+iOS Safari best (reconstructs delta frames, tolerates sparse keyframes); Chrome needs keyframe every ~5 frames; Firefox is choppy on MP4 even with dense keyframes and needs a VP9 .webm twin (`-vcodec libvpx-vp9 -g 2` / keyint=2); iOS Safari won't play webm, so ship BOTH mp4+webm. All-intra inflates size ~3-5x vs normal GOP, so scrub segments must be short (2-4s, 1440p max — the gist scales to 1440 tall). AV1 cannot be the universal scrub codec: Apple has no software AV1 decoder; hardware decode only on iPhone 15 Pro/16 (A17 Pro+) and M3+ Macs (Bitmovin). Seeking is not frame-accurate (web.dev rVFC article), so lerp a target time and only issue the next seek after the 'seeked' event; requestVideoFrameCallback (Chrome 83+, Safari 15.4+, Firefox 132+) tells you when the new frame actually hit the compositor.

**Fit for this project:** Use scrub segments for at most 2-3 hero beats (SB-09 door lift, SB-02 garage door blade of light) generated image-to-video from the existing graded stills, re-encoded all-intra. The other plates should NOT be scrubbed video — cheaper tiers read better and protect the LCP/CLS gates.

### Canvas frame-sequence + WebCodecs (the Apple technique) and iOS memory ceiling

Apple's AirPods Pro page draws a ~148-frame JPEG sequence to <canvas> keyed to scroll (CSS-Tricks writeup) — frame-accurate and reverse-scrub-proof, at the cost of bandwidth (150 frames x 40-80KB ≈ 6-12MB per moment). The 2024+ upgrade is WebCodecs: demux MP4 with mp4box.js, VideoDecoder → ImageBitmaps → canvas (lionkeng tutorial); VideoDecoder ships in Safari 16.4+ (video interfaces only, no audio until 18.x; known breakages 16.4-18.7 per webstatus/testmu). Hard iOS Safari limit: total canvas buffer memory ~384MB on iOS 15+ (earlier WebKit 224-288MB; webkit bug 195325, PQINA) — a decoded 1080p RGBA frame is ~8.3MB, so a full 150-frame cache (1.2GB) crashes the tab. Keep a sliding window of <=20 decoded frames and zero canvas width/height on unmount (Safari hoards freed canvases).

**Fit for this project:** Reserve canvas/WebCodecs for ONE desktop-only money moment if scrub-on-video proves janky (e.g., SB-19 wrap reveal). On mobile always fall back to the video-seek tier or the still. Never hold more than a ~20-frame decoded window.

### Ambient loops — the primary 'living scene' mechanism

Best practice: 4-8s seamless loops, muted+playsinline+autoplay+loop+poster, preload=none/metadata until near-viewport (Chrome prebuffers 25s on desktop but ZERO on iOS/Android — web.dev). Autoplay is refused in iOS Low Power Mode and under Save-Data: call video.play(), catch the rejected promise, and leave the poster still showing (lesniakrafal/Bitmovin). Encode ladder: H.264 High CRF ~18-20 1080p (universal, ~1.5-2.5MB per 5s loop) + optional HEVC/AV1 variant via <source> order for smaller files on capable devices. Seamless looping: generate with matched first/last frames or ping-pong the segment; strip audio (-an).

**Fit for this project:** This is how 20+ of the 24 beats come alive at Hollywood grade: image-to-video 5s loops from each graded still (atmosphere drift, heat shimmer, headlight flare, hair/fabric motion), crossfaded exactly like today's plates. The current PNG becomes the poster, so slow-connection/reduced-motion/Low-Power users get precisely today's working experience — ship-gate preserved by construction.

### GSAP ScrollTrigger vs framer-motion 12 + Lenis (verdict: keep the stack)

ScrollTrigger is the industry default for multi-timeline pin/scrub choreography and became 100% free (incl. SplitText/MorphSVG) after the Webflow acquisition, April 2025. But motion.dev's useScroll now runs eligible animations on the native ScrollTimeline API (GPU-composited opacity/transform/filter — exactly what the plate crossfade and de-blur use), and Lenis's own docs define the GSAP bridge (lenis.on('scroll', ScrollTrigger.update) + gsap.ticker.add + lagSmoothing(0)) if you ever need it. Running two RAF-driven animation systems against one pinned viewport invites double-update jank; the CinematicStage design (one useScroll progress, N-1 fade bands) doesn't need ScrollTrigger's pin management because the pin already works.

**Fit for this project:** Keep Lenis + framer-motion 12. Drive video tiers from the same scrollYProgress via useMotionValueEvent → seek/play logic. Only reconsider GSAP if a future beat needs nested pinned sub-timelines or snap-to-beat.

### Delivery: move video off Netlify to Cloudflare R2; Stream/Mux only if streaming features needed

## 4.4 Engineering plan (how CinematicStage evolves)

CINEMATICSTAGE EVOLUTION — the core insight is that nothing about the scroll math changes: one useScroll progress, plates cross-dissolving in N-1 fade bands, copy blocks beneath at 100svh each. Each plate becomes a discriminated union: type Plate = StillPlate | LoopPlate | ScrubPlate | DepthPlate | RivePlate (hybrid = Depth/Loop + Rive overlay). Every plate renders POSTER-FIRST: the AVIF/WebP still paints immediately (it IS the LCP and the reduced-motion/Save-Data/Low-Power/slow-connection path), and the living layer crossfades in over it only after it signals ready (loadeddata for video, shader-compiled for WebGL, Rive load event). WINDOWED MOUNTING: only the active plate ±1 mounts its living layer; everything else is poster-only; video elements set preload='none' until within 2 bands, then preload='auto'. Unmounting zeroes video src and canvas width/height (Safari hoards freed canvases). LOOP PLATES: <video muted playsInline autoPlay loop poster={still} disableRemotePlayback>, promise-checked play() — on rejection (iOS Low Power Mode, Save-Data) silently stay on the poster. Because posters are extracted frame-0 of the delivered loop, the crossfade is invisible. SCRUB PLATES (max 4-5 beats): derive a plate-local progress with useTransform(scrollYProgress, [bandStart, bandEnd], [0,1]); useMotionValueEvent drives a lerped target currentTime with seek-gating — never issue the next seek until the 'seeked' event fires; use requestVideoFrameCallback where available to confirm compositor delivery; <source> order mp4 (all-intra H.264 baseline) then webm (VP9 keyint=2) — Firefox needs the webm, iOS ignores it. AV1 is banned as the universal codec (no Apple software decoder). Optional desktop-only upgrade for SB-19: WebCodecs sliding-window canvas (mp4box.js demux, VideoDecoder, <=20 decoded frames ~170MB ceiling), gated by 'VideoDecoder' in window && !isTouchDevice; iOS NEVER gets WebCodecs (384MB total canvas memory ceiling, 224MB on some builds). DEPTH PLATES: ONE shared client island (dynamic import, ssr:false per Netlify SSR constraint) — an OGL or @react-three/fiber fullscreen quad whose fragment shader offsets UVs by the depth map scaled by scroll delta + pointer, clamped to ~±20px to avoid edge stretching, plus shared grain/vignette uniforms matching the locked film-noir grade; depth maps are build artifacts, never computed client-side. Prefer OGL (~tens of KB) over three.js unless we add more 3D later. GSAP VERDICT: DO NOT ADD. framer-motion 12's useScroll rides the native ScrollTimeline GPU path for exactly the properties we animate (opacity/transform/filter); two RAF systems against one pinned viewport invites double-update jank; Lenis's GSAP bridge exists if a future beat truly needs nested pinned timelines — none of the 24 do. GAUGE SWEEP (SB-11): build in Rive — artboard with needle sweep + RPM count-up + one Gulf-blue #6CBDE6 telemetry tick (the single accent), a state-machine number input 'progress' bound to the plate-local scroll progress via @rive-app/react-canvas client island. This is the exact OFF+BRAND/Lando Norris award pattern; files ~10-15x smaller than Lottie, GPU-rendered. Reuse the artboard for telemetry accents on SB-13/SB-16. MEDIA CDN: all mp4/webm on Cloudflare R2 ($0.015/GB-mo, ZERO egress, byte-range requests — required for currentTime seeking) behind media.driveexotiq.com with cache-everything + immutable headers; ~70MB total sits inside R2's free tier. Netlify keeps HTML/JS/posters only — its 2026 credit pricing (20 credits/GB bandwidth vs 1,000 credits on Pro) would exhaust at ~800 video-viewing visits/month. PERF BUDGET: LCP = SB-01 poster AVIF (preloaded, <200KB); zero video bytes before first interaction; CLS protected by fixed-aspect plate containers (unchanged); total media transfer for a full scroll-through targeted <25MB on desktop, <10MB on mobile (mobile can serve 720p loop variants via media query on <source>). prefers-reduced-motion keeps the existing static stacked fallback untouched — living layers are pure progressive enhancement.

## 4.7 Risks & mitigations

- Car-specific video artifacts (wheel-spoke morphing, grille warp, badge/plate text scramble, swimming reflections) — cars are the hardest consistency genre. MITIGATION: always i2v from locked graded stills, prompt wheels static/motion-blurred in loops, favor camera moves over object deformation, 3-5 takes with the per-take QA checklist recorded in the manifest, Seedance reference-to-video as the identity-lock fallback; human curation is the final gate.
- iOS Safari kills the experience (autoplay refused in Low Power Mode, ~384MB canvas memory ceiling, zero mobile prebuffering). MITIGATION: poster-first architecture makes the still the guaranteed baseline; promise-checked play() with silent fallback; WebCodecs desktop-only with a <=20-frame window; preload='none' until near-viewport; a Low-Power-Mode device test is a Phase 1 exit criterion.
- Netlify bandwidth billing blowout (20 credits/GB vs 1,000/month on Pro — ~800 video visits exhausts it). MITIGATION: R2 with zero egress is a Phase 0 exit criterion; NO video plate ships before media.driveexotiq.com is live; posters stay on Netlify so LCP is unaffected.
- Scrub jank on Firefox and low-end devices (MP4 seeking is choppy there even all-intra). MITIGATION: VP9 keyint=2 webm twins, seek-gating on 'seeked', scrub limited to 4-5 beats, per-device downgrade path scrub -> loop -> still; if a scrub beat can't hit 45fps+ on mid-tier hardware it ships as a loop.
- Loop seams visible under the ken-burns stage. MITIGATION: Kling start=end frame produces pixel-exact returns; poster extracted from frame 0 of the delivered file guarantees an invisible still-to-video handoff; ping-pong encode and Luma loop:true as fallbacks.
- Still re-render drifts the approved grade or breaks still/video sync (a regenerated still no longer matches its already-generated loop). MITIGATION: videos generate from CURRENT approved stills first; 4K re-renders are scoped to depth-tier beats and posters; any beat whose source still changes gets its loop regenerated (cheap: ~$0.90/loop); one approved master plate rides every image call as a style reference.
- Model/vendor churn mid-build (Sora already sunsetting; Veo 3.0 shut down June 2026 — preview-suffixed models move fast). MITIGATION: Sora excluded by design; beats-manifest.json keeps model routing declarative so an engine swap is a one-line change; all masters, prompts, seeds, and take selections are committed so any beat is regenerable on a successor model.
- Award-chasing effects regress the conversion page (LCP/CLS/INP or CTA visibility). MITIGATION: Lighthouse budgets enforced in CI from Phase 0; persistent chrome CTAs untouched; posters remain the LCP; scroll-depth + CTA analytics in Phase 4 provide a rollback trigger per beat — every living layer can be disabled by flipping its manifest entry back to 'still'.
